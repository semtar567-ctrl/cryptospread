# CryptoSpread - Product Vision (Telegram UI/UX)

## Основная концепция
Вся работа с платформой происходит через Telegram-бота. Бот выступает в роли панели управления (Dashboard) и системы алертов.

## Сценарий использования (User Journey)
1. **Выбор типа торговли:** Пользователь выбирает направление арбитража (например, Фьючерс-Фьючерс, Спот-Фьючерс и т.д.).
2. **Настройка фильтров (с возможностью вкл/выкл каждого):**
   - **Минимальный спред:** Порог в процентах для поиска связки.
   - **Минимальный объем за 24ч:** Фильтр от неликвидных и опасных монет.
   - **Рабочий объем (размер позиции):** Пользователь вводит сумму в USD, на которую планирует заходить на каждой бирже. Система должна рассчитывать **реальный спред с учетом проскальзывания (slippage)**, "съедая" стакан на этот объем.
   - **Время жизни связки:** Сколько времени спред должен держаться выше порога (например, 3 секунды), чтобы отсеять микро-прострелы и ложные срабатывания, в которые нельзя успеть зайти руками.
3. **Управление биржами:** Возможность включать и отключать конкретные биржи из поиска.
4. **Отслеживание и схождение (Exit Strategy):**
   - Возможность подписаться на отслеживание конкретной найденной связки (в которую пользователь зашел руками).
   - Установка "процента схождения" (target exit). Бот должен прислать уведомление, когда спред сузится до этого значения, чтобы пользователь мог закрыть позиции с прибылью.

## Технические следствия для архитектуры
- **Стаканы (Orderbooks):** Потребуется собирать стаканы достаточной глубины (больше 1 уровня), чтобы корректно считать проскальзывание на заданный пользователем рабочий объем.
- **База данных:** Нужна БД (например, PostgreSQL или SQLite) для хранения настроек пользователя в Telegram, состояния фильтров и списка "отслеживаемых" связок.
- **Signal Engine (Python):** Должен уметь хранить состояние (State) во времени, чтобы отсчитывать "время жизни связки".
