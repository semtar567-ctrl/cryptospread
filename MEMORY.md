# Memory проекта CryptoSpread

## Текущий статус [30.05.2026]
**СТАБИЛЬНАЯ ВЕРСИЯ v6 РЕАЛИЗОВАНА.** Внедрено "Идеальное Ядро" на базе Tick Loop (100мс) и оптимизации `is_dirty`. Восстановлена работа всех основных коллекторов.

### Выполненные действия:
1. **Оптимизация Ядра (Rust):**
   - Внедрена структура `OrderBookState` с флагом `is_dirty`.
   - Основной цикл аналитики переведен на частоту 100мс (в 10 раз быстрее предыдущей версии).
   - Реализована проверка `is_dirty`: спреды считаются только при наличии новых данных от WS.
2. **Коллекторы:**
   - **Binance:** Исправлен URL (переход на `/stream`) и формат обработки Combined Streams. Активирован поток `depth20@100ms`.
   - **MEXC:** Коллектор раскомментирован и проверен на совместимость с новыми моделями.
   - **Bybit/OKX:** Подтверждена стабильная работа в новом цикле.
3. **Качество кода:**
   - Проведена успешная компиляция всей системы Rust Core.
   - Окружение Python синхронизировано через `uv sync`.

### Ближайшие шаги:
1. **Тестирование на живых данных:** Запустить систему и убедиться в корректности прихода сигналов в Telegram.
2. **Фильтрация ложных прострелов:** Настроить параметр `min_lifetime_seconds` в Python Engine, используя новые высокочастотные данные из Ядра.
3. **Историческое логирование:** Начать запись спредов в PostgreSQL для последующего анализа качества сигналов.

### Инструкция по запуску (v6):
1. **Rust Core:** `cd rust_core; cargo run --release` (Рекомендуется release для максимальной производительности Tick Loop).
2. **Signal Engine:** `uv run signal_engine/main.py`
3. **Telegram Bot:** `uv run telegram_bot/main.py`
