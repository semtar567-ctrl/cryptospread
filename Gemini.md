# АРХИТЕКТУРНЫЙ СТАНДАРТ (v6 "Идеальное Ядро")

Система разделена на высокопроизводительное Ядро и гибкий Движок Сигналов.

### 1. Rust Core (Performance Layer)
- **Роль:** Сбор данных (WebSocket), нормализация стаканов, расчет сырых спредов.
- **Tick Loop:** Основной цикл аналитики строго 100мс.
- **Оптимизация `is_dirty`:** Расчеты производятся только для символов, получивших обновление от WS (флаг сбрасывается после тика).
- **Stale Data Detection:** Данные старше 3 секунд считаются "протухшими" и игнорируются.
- **Dynamic Config:** Поддержка мгновенного обновления настроек через Redis Pub/Sub (`user_updates`).

### 2. Python Engine (Intelligence Layer)
- **Роль:** Обогащение сигналов метаданными (фандинг, объемы), фильтрация по времени жизни (`min_lifetime`), доставка в Telegram.
- **Throttling:** Строгий контроль частоты сообщений (1.1 сек между алертами) для защиты от Flood Control Telegram.
- **Deduplication:** Анти-спам логика (60 секунд на повторную связку).

### 3. Коммуникация
- **Redis Streams (`market_signals`):** Единственный канал передачи сигналов из Rust в Python.
- **Redis K/V (`meta:*`):** Хранилище метаданных о рынке.
- **PostgreSQL:** Единственный источник правды для настроек пользователей и истории сигналов.

# СТАНДАРТЫ РАЗРАБОТКИ

### Rust Standards
- Использование `Tokio` для асинхронности.
- `DashMap` для потокобезопасного хранения состояния рынка.
- Минимум аллокаций в горячих путях (Tick Loop).
- Строгая типизация через `serde` и `anyhow`.

### Python Standards
- **Python 3.12+** и менеджер пакетов `uv`.
- Асинхронность через `asyncio`. **Запрещено блокировать event loop.**
- Структурированное логирование через `structlog`.
- Типизация через `mypy` везде, где это возможно.

### Качество Сигналов (Priority)
1. **VWAP Calculation:** Все расчеты доходности должны учитывать рабочий объем пользователя (`working_volume_usd`) и проскальзывание.
2. **Fee Awareness:** Всегда учитывать комиссии (`taker_fee`) обеих бирж.
3. **Funding Impact:** Сигнал должен отображать спред фандинга и время до следующей выплаты.
4. **False Positive Reduction:** Приоритет точности над количеством. Лучше пропустить сигнал, чем прислать ложный.

# ОПЕРАЦИОННЫЙ РЕЖИМ

### Оркестрация
- **`watchdog.py`** — единственный легитимный способ запуска всей системы в сборе. 
- Любой новый сервис должен быть интегрирован в Watchdog.

### Управление состоянием (MEMORY.md)
- Файл `MEMORY.md` является обязательным индексом прогресса.
- Обновляется СТРОГО после каждой выполненной задачи.
- Должен содержать актуальные инструкции по запуску и "Ближайшие шаги".

### Безопасность и Стабильность
- **Никаких секретов в коде:** Все ключи только в `.env`.
- **Graceful Shutdown:** Все компоненты должны корректно закрывать соединения при остановке.
- **Retry Logic:** Экспоненциальный бэк-офф для всех сетевых подключений.

# ПРАВИЛА AI-АССИСТЕНТА
1. **Исследование:** Перед правкой кода всегда изучать `MEMORY.md` и текущую структуру папок.
2. **Валидация:** После правок в Rust — `cargo check`, в Python — запуск тестов или линтера.
3. **Отчетность:** После каждого этапа давать краткий отчет: что сделано, как проверить, что делать дальше.
4. **Чистота:** Не плодить временные файлы в корне. Тесты — в `tests/`, логи — в `logs/` или файлы `.log`.
